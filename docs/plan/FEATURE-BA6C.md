# FEATURE-BA6C — New icon set without the tile

**Status:** TODO

## Objective

Replace the application icon with the new set in `C:\Dev\EnigmaLibs\Branding\Apps\final2\hardcopy` (`.ico`, ten
PNG frames, two SVG masters). Update every place the repository carries it: the executable and window icon, the
About dialog's image, the Linux installer's icons and the SVG masters.

## Context & constraints

- **The new artwork** is the same drawing as FEATURE-1148's (a QR code in the *Soft* palette: `#6A9BF4` modules,
  a `#63C77D` corner module), **without the dark rounded tile**: the background is transparent, and the finder
  patterns' dark rings are holes (even-odd paths) instead of tile-coloured squares. Generated by
  `Branding/Apps/export.py final2`, which the SVGs' header comments name.
- **The new `.ico`** holds the same ten 32-bit PNG frames as today (16, 20, 24, 32, 40, 48, 64, 96, 128, 256); each
  frame is byte for byte the matching `png/enigma-hardcopy-N.png` (checked while planning).
- **Where the icon lives** today, every copy byte-identical to the old `final/hardcopy` set:
  - `src/Enigma.HardCopy.Desktop/Assets/app.ico`: the `ApplicationIcon`, `MainWindow`'s `Icon`, and the `app.ico`
    copied beside the executable (FEATURE-C5C6);
  - `src/Enigma.HardCopy.Desktop/Assets/app-256.png`: the About dialog's image (FEATURE-7B95);
  - `packaging/icon/enigma-hardcopy.svg`, `enigma-hardcopy-small.svg`: the masters;
  - `packaging/linux/icons/enigma-hardcopy-{16,24,32,48,64,96,128,256}.png`: what `install.sh` installs
    (`ICON_SIZES`).
- **Android (HardCopy Recover)** draws its launcher icon as vector drawables, not from these files. Its adaptive
  foreground (`drawable/app_icon_foreground.xml`) is already this exact drawing (same module coordinates, finder
  patterns as even-odd holes); only the background layer, `@color/app_icon_background` `#1E1F22`, is the tile.
- `AppIconTests` pins the `.ico` frames, the PNG's size and the output copy; `LinuxPackagingTests` pins the Linux
  PNGs' sizes. Neither checks that the copies agree with each other.

## Steps

1. Copy, byte for byte:
   - `enigma-hardcopy.ico` → `src/Enigma.HardCopy.Desktop/Assets/app.ico`;
   - `png/enigma-hardcopy-256.png` → `src/Enigma.HardCopy.Desktop/Assets/app-256.png`;
   - the two SVGs → `packaging/icon/`;
   - the 16, 24, 32, 48, 64, 96, 128 and 256 PNGs → `packaging/linux/icons/`.
2. Android: the artwork stays. The comments in `app_icon_foreground.xml` and `values/colors.xml` that cite
   `Branding/Apps/final/hardcopy` name the in-repository master `packaging/icon/enigma-hardcopy.svg` instead, and
   say the background layer is where the tile lives on Android.
3. `AppIconTests`: two new facts —
   - `app-256.png` is the `.ico`'s 256 frame byte for byte;
   - each Linux PNG is the `.ico` frame of its size byte for byte.
4. Check that no prose describes the desktop icon's dark tile as current (README, comments). Fix any that does.
5. Release build, whole suite, `cmp` of every destination.

## Acceptance criteria

- The four destinations hold the new files byte for byte (`cmp`), and no old file is left.
- The new `AppIconTests` facts pass, as do the existing icon and Linux packaging tests.
- The Android head builds; its resources are unchanged except for comments.
- The Release build has zero warnings beyond the run's baseline; the whole suite shows no new failure.

## Out of scope

- The Android launcher artwork's colours or shape.
- Release notes and version (FEATURE-C1D1).
- Changing the sizes the Linux installer installs (still eight).
